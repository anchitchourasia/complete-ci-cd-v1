## 2. In-Depth Operational & Technical Concepts

### A. Repository Checkout Paths vs. External Host Paths
The runner uses two distinct filesystem concepts:
1. **GitHub Workspace Path (`$env:GITHUB_WORKSPACE`)**: The temporary directory managed by the GitHub Actions runner agent (e.g., `D:\runner\_work\VPMS_Frontend\VPMS_Frontend` or the checkout folder). Actions like `actions/checkout@v4` unpack repositories here.
2. **Fixed Host Paths**: Hardcoded absolute drive paths like `D:\frontend pipeline\VPMS_Frontend\...`, `C:\maven\...`, and `E:\apache-tomcat-10.1.28\...`. If the workspace root changes or multiple runners are introduced, hardcoded paths will fail.

### B. Host File Paths vs. Container File Paths
A frequent source of misconfiguration is referencing Windows host paths inside Linux containers:
- **`app.upload.dir=D:/cvps/uploads`**: In [`application.properties#L52`](file:///D:/frontend%20pipeline/VPMS_Frontend/backend/src/main/resources/application.properties#L52), this property specifies a Windows drive letter path. Inside the backend Linux Alpine container (`eclipse-temurin:17-jdk-alpine`), the filesystem is POSIX. Java will attempt to create a directory named `D:/cvps/uploads` relative to the container root (`/app/D:/cvps/uploads`), which will fail or lose data when the container is recreated unless bound to a volume.

### C. Tomcat `setenv.bat` vs. Container Environment Variables
- In external Tomcat, JVM arguments cannot be passed via Docker commands. Instead, Tomcat executes `bin/setenv.bat` upon startup, appending `-Dspring.config.additional-location=...` to `CATALINA_OPTS`.
- In Docker, Compose sets the environment variable `SPRING_CONFIG_ADDITIONAL_LOCATION: file:/config/application.properties`, which Spring Boot automatically translates into the same configuration override.

### D. Angular Build-Time vs. Spring Boot Runtime
- **Angular**: Builds with esbuild/Vite into static JavaScript. `environment.ts` is evaluated **at compile time**. No runtime environment variables exist in client-side JavaScript.
- **Spring Boot**: Evaluates `application.properties` **at runtime boot**. Property overrides can be mounted without rebuilding JAR/WAR files.

### E. Why Missing Bind Mount Sources Become Directories
In Docker Compose short volume syntax (`<source>:<dest>`):
- If the `<source>` file on the host machine **does not exist** when `docker compose up` executes, Docker Engine automatically creates a **directory** with that name on the host and mounts that directory into the container!
- This causes Spring Boot to fail with a `FileNotFoundException` or `EISDIR` (directory instead of file) when attempting to parse `application.properties`.

### F. The Scope of `localhost`
- When the **browser** resolves `localhost`, it refers to the end-user's workstation.
- When a **container** resolves `localhost`, it refers to the isolated loopback interface inside that specific container—**not** the Windows host and **not** other containers.
- When the **runner agent** resolves `localhost`, it refers to the Windows host machine.

## 3. Configuration Change Matrix

| Configuration Change | Location | Requires Recompile? | Requires Docker Build? | Requires Container Recreation? | Requires Tomcat Restart? |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Angular API Base URL | `Frontend/src/environments/environment.ts` | **Yes (`ng build`)** | **Yes** | **Yes (`compose up`)** | No |
| Frontend Nginx routing | `Frontend/nginx.conf` | No | **Yes** | **Yes (`compose up`)** | No |
| Database Password / URL | `backend/src/.../application.properties` | No | No | **Yes (`restart backend`)** | **Yes** |
| Spring Java Controller Code | `backend/src/main/java/...` | **Yes (`mvn package`)** | **Yes** | **Yes (`compose up`)** | **Yes (Re-copy WAR)** |
| Docker Port Mapping | `docker-compose.yml` | No | No | **Yes (`compose up`)** | No |
| Tomcat Port | `E:\apache-tomcat-10.1.28\conf\server.xml` | No | No | No | **Yes** |
